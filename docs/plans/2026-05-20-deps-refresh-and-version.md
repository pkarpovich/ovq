# Deps refresh, serde-saphyr migration, --version flag

## Overview

Three pieces of routine maintenance bundled into one release cycle:

1. Add the `--version` flag that v0.3.0 turned out to be missing. Surfaces via clap derive's built-in support; trivial change.
2. Bump the Rust toolchain pin from `1.92` to `1.95` (latest stable per `mise latest rust`).
3. Replace `serde_yaml = "0.9"` with `serde-saphyr` so we sit on an actively-maintained YAML stack. As a bonus, since serde-saphyr can deserialize directly into `serde_json::Value`, we drop the `yaml_to_json` walker and use one unified Value type for both YAML input and JSON output.

The end product is shipped as v0.3.1.

## Context (from discovery)

- Active codebase as of v0.3.0: 8 source files, ~1300 LOC including the new `output.rs`. 65 unit tests inline per file.
- Files involved in the migration:
  - `Cargo.toml` - dependency edit, version bump
  - `Cargo.lock` - regenerated by `cargo build`
  - `.mise.toml` - rust toolchain pin
  - `src/main.rs` - `--version` flag, plus `serde_yaml::Value` types swapped to `serde_json::Value`
  - `src/frontmatter.rs` - parsing entry point, returns `serde_json::Value` now
  - `src/query/eval.rs` - walks `serde_json::Value` instead of `serde_yaml::Value`
  - `src/values.rs` - aggregates over `serde_json::Value`
  - `src/output.rs` - `yaml_to_json` helper deleted; `format_json_query` no longer converts
- Patterns to follow: same as v0.3.0 (inline `#[cfg(test)] mod tests`, ExitCode helpers, clap derive). The `rust-style` and `rustdoc` skills give the house style.
- Recent: master is at `85aad38` (v0.3.0 release merge, PR #2). All previous work is shipped.

## Design decisions (locked upfront)

- **YAML target type is `serde_json::Value`.** serde-saphyr has no native `Value` enum; it deserializes into a known type. Targeting `serde_json::Value` gives us a generic untyped tree that matches our JSON output type and lets us delete the `yaml_to_json` walker. This is the architectural simplification the migration buys.
- **`serde_yaml_ng` rejected.** Stagnant since 2024-05; community-favoured but unmaintained. serde-saphyr is the active path forward.
- **`yaml-rust2` direct rejected.** Activem but requires writing our own serde adapter or a ~500 LOC rewrite away from serde. Out of scope.
- **`--version` uses clap's built-in handling.** Adding `#[command(version)]` on the `Cli` struct is enough; clap reads the version from `Cargo.toml` automatically.
- **Rust toolchain.** Pinned to `1.95.0` explicitly (not `latest`) per Pavel's preference from the turtle-harbor PR #19 deps-refresh.
- **Release version.** v0.3.1 (patch bump; no CLI surface changes, only the missing `--version` flag and internal migration).

## Implementation Steps

### Task 1: Add `--version` flag to the CLI

- [x] Add `#[command(version)]` to the `Cli` struct in `src/main.rs`. The version string is read from `Cargo.toml` automatically.
- [x] Write a unit test that ensures `clap::Parser::try_parse_from(&["ovq", "--version"])` returns a recognisable error variant that clap raises for the `--version` flag (`ErrorKind::DisplayVersion`).
- [x] Run `cargo test`; new test plus existing 65 must pass.

### Task 2: Bump Rust toolchain pin

- [ ] Update `.mise.toml` from `rust = "1.92"` to `rust = "1.95"`.
- [ ] Run `mise install` (or `mise use`) to pull the toolchain locally.
- [ ] Run `cargo build --release` and `cargo test`. Both must succeed on the new toolchain without code changes.
- [ ] No new tests added; toolchain bump is a config change with no behavioural surface.

**What we get across 1.93, 1.94, 1.95 - and why we are not refactoring to use any of it in this plan:**

| Version | Headline feature | Applies to ovq? |
|---|---|---|
| 1.93 (Jan 2026) | asm! cfg per statement, musl 1.2.5, thread_local re-entrancy fixes, 23 stabilised APIs | No specific match in ovq |
| 1.94 (Mar 2026) | `array_windows` slice iterator, AVX-512 FP16 / NEON FP16 intrinsics, 29 RISC-V target features, Cargo `include` config key, Cargo `pubtime` registry index field | No - ovq has no sliding-window iteration, no SIMD, no cross-target builds, Cargo.toml is single-file simple |
| 1.95 (Apr 2026) | `cfg_select!` macro (replaces cfg-if crate), **`if let` guards in `match` arms**, multi-package publishing | **`if let` guards could clean up two or three `match` arms in `src/query/eval.rs`** but this is a separate refactor, not part of this plan. Toolchain bump is the unlock; usage is opt-in later. |

Rust 1.95's `if let` guards in match arms is the only feature with a real future application to our codebase. We deliberately do not refactor in this plan (per surgical-changes rule); a follow-up plan can pick it up if and when the pattern starts to feel awkward in `query/eval.rs`.

### Task 3: Refresh transitive dependencies

- [ ] Run `cargo update` to pull the latest within the existing semver-compatible ranges. Direct deps stay at their declared majors (`clap = "4"`, `serde = "1"`, etc.), only `Cargo.lock` changes.
- [ ] Run `cargo build --release` and `cargo test`. Must pass unchanged.
- [ ] Run `cargo audit` (install via `cargo install cargo-audit` if not present). All advisories must be clean or annotated in this plan as deliberate accepted risk.

### Task 4: Replace serde_yaml with serde-saphyr targeting `serde_json::Value`

- [ ] Edit `Cargo.toml`: remove `serde_yaml = "0.9"`; add `serde-saphyr = "0.0.26"` (or whatever is the latest stable at the time of the run - confirm with `cargo search serde-saphyr` before committing).
- [ ] In `src/frontmatter.rs`, change the `parse_frontmatter` return type from `Option<serde_yaml::Value>` to `Option<serde_json::Value>`. Inside, call `serde_saphyr::from_str::<serde_json::Value>(yaml_text)` instead of `serde_yaml::from_str`. Decide the exact function name in code; the type signature change is the load-bearing part.
- [ ] In every site that imported `serde_yaml as Yaml` / `serde_yaml::Value`, swap to `serde_json::Value`. Files: `src/main.rs`, `src/query/eval.rs`, `src/values.rs`, `src/output.rs`.
- [ ] In `src/output.rs`, delete the `yaml_to_json` walker (and its tests) - it is now redundant because the input is already `serde_json::Value`. `format_json_query` simplifies: the `frontmatter` field is just the value directly, no walk needed.
- [ ] Adapt every existing test that constructs a `serde_yaml::Value` literal to construct a `serde_json::Value` instead (typically via `serde_json::json!(...)` macro). Tests stay inline.
- [ ] Add one new test in `src/frontmatter.rs` that parses a fixture with a YAML date (`2024-12-16`) and asserts it lands as an ISO 8601 string in the resulting `serde_json::Value` (preserving the behaviour ADR 0001 required from the v0.3.0 plan).
- [ ] Add one new test that parses a fixture with a YAML array of strings and asserts the resulting `serde_json::Value` is a JSON array (not a single string), as serde-saphyr should preserve list shape.
- [ ] Run `cargo test`. All 65 existing tests plus the two new ones must pass. Any failing test is a real behavioural difference and must be triaged before continuing.
- [ ] Run `cargo clippy --all-targets -- -D warnings`. Clean.
